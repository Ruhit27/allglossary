Documentation ("docs") explains code to people. It ranges from a project's readme — what this is, how to install and run it — to guides, tutorials, and references listing every [function](./Function.md) in an [API](./API.md) with its [parameters](./Parameter.md) and [return values](./Return%20value.md).

Good documentation saves enormous time, for new team members, for other developers using your [library](./Library.md), and for yourself in a year. [Comments](./Comment.md) explain individual tricky lines; documentation explains the bigger picture.

Like comments, docs go stale when code changes and they don't. Keeping them next to the code, and updating both together, helps.

_Avoid:_ "the code is the documentation" — code shows what it does, but not why, or how others should use it.

_Usage:_

"How do I use the export function?"

"Check the documentation — it lists every option with examples."
