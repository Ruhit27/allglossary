description: A ready-made foundation of code and conventions for building websites, such as React, Vue or Next.js.
---

Building a large site from raw [JavaScript](./JavaScript.md) means solving the same problems over and over: keeping the screen in sync with data, organizing code, handling navigation. A framework solves them once, so you build on top. Popular frontend examples include React, Vue, Svelte and Angular; backend examples include Django, Rails and Express.

Most frontend frameworks are built around [components](./Component.md) and update the [DOM](./DOM.md) for you when data changes. Some, like Next.js, cover both [client-side](./Client-side%20rendering.md) and [server-side rendering](./Server-side%20rendering.md) and include a [bundler](./Bundler.md).

Frameworks speed up development and give teams a shared way of working, but they add weight and change often. Picking one is a long-term commitment.

_Avoid:_ "framework" and "language" as the same — React is written in JavaScript; it's a toolkit, not a new language.

_Usage:_

"Should we rebuild the marketing site in React?"

"It's five pages of text. Plain HTML or a static site generator would be faster and simpler."
